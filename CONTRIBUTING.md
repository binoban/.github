# Contributing to Binoban

Thanks for your interest in contributing to Binoban's public repositories.

This file is an organization-wide default. Individual repositories may include their own
`CONTRIBUTING.md` with project-specific guidance — that takes precedence.

## Ways to contribute

- **Report bugs** — open an issue using the repository's issue templates. Include
  versions, environment, and reproduction steps.
- **Suggest improvements** — open an issue describing the problem and the outcome you'd
  like.
- **Submit changes** — open a pull request against `main`. Keep changes small, focused,
  and well described.

## Pull request guidelines

- Describe what changes and why. Link any related issue.
- Match the existing code style and conventions of the repository.
- Keep public-facing examples, SDKs, and docs aligned with Binoban naming standards
  (e.g. Advertiser Portal, Retail Media, Supply / SSP, Exchange).
- Never include real credentials, customer-specific data, or non-production hosts. Use
  documented placeholders.

## Ground rules

- Be respectful and constructive — see our [Code of Conduct](CODE_OF_CONDUCT.md).
- For security issues, **do not** open a public issue — see [SECURITY.md](SECURITY.md).
- For account, credential, or deployment questions, contact **support@binoban.io**.
